# Google Play 출시 정책

> 마지막 정리: 2026-11-03. targetSdk 36 요건(2026-08-31부터)과 개인 계정 테스터 12명×14일은 2026-11-03 조사로 재확인 (data/research/map-osm.md). Play 정책은 자주 바뀐다. 출시 전에는 아래 항목을 [Play Console 고객센터](https://support.google.com/googleplay/android-developer)와 [Android 개발자 문서](https://developer.android.com)에서 다시 확인하고 이 날짜를 갱신한다.

## 1. 빌드 요건

- **배포 형식은 Android App Bundle(`.aab`)**. APK는 테스트용으로만.
- **targetSdk**: Play는 매년 8월 31일 기준으로 신규 앱·업데이트가 "최신 Android 버전 출시 후 1년 이내" API 레벨을 타깃하도록 요구한다. 2026-11 기준으로는 **API 36(Android 16)**. 빌드 설정을 건드릴 때마다 현재 요건을 확인한다.
- **minSdk**: 저사양·구형 폰 사용자가 많으므로 가능한 낮게 잡는다(기본 목표 API 24, Android 7.0). 지도 SDK가 요구하는 최소 버전을 넘지 않게.
- **16KB 메모리 페이지 크기 지원**: Android 15 이상을 타깃하는 앱은 네이티브 라이브러리(.so)가 16KB 페이지에 맞게 정렬돼 있어야 한다. **2027-02-01부터는 16KB를 지원하지 않는 업데이트는 출시할 수 없다** (data/research/map-osm.md). 현재 지도는 순수 Dart(flutter_map)라 네이티브 지도 SDK는 없지만, Flutter 엔진·플러그인(geolocator 등) 버전을 확인한다.
- **앱 서명**: Play App Signing 사용. 업로드 키스토어는 저장소 밖에 보관하고, 분실 대비 백업 위치를 사용자에게 알린다.
- **앱 크기**: 데이터 요금 부담이 있는 사용자를 위해 작게 유지한다. 목표 설치 크기 20MB 이하. 큰 리소스(지도 타일 등)를 번들에 넣지 않는다.
- 릴리스 빌드는 코드 축소·난독화(R8) 켜기. 디버그 로그는 릴리스에서 제거.

## 2. 개발자 계정·테스트 트랙

- 2023-11 이후 만든 **개인 개발자 계정**은 프로덕션 출시 전에 **비공개 테스트에 최소 12명이 14일 연속 참여**해야 한다(조건은 바뀔 수 있으니 확인).
  - 실제 사용자(노숙인 지원기관 실무자, 쪽방상담소, 자원봉사자)를 테스터로 모으면 요건 충족과 현장 검증을 동시에 할 수 있다.
- 조직 계정(비영리 단체·법인)으로 등록하면 이 요건이 없고 신뢰도도 높다. 운영 주체가 정해지면 검토.
- 출시 순서: 내부 테스트 → 비공개 테스트 → 프로덕션(단계적 출시 10% → 50% → 100%).

## 3. 권한

| 권한 | 사용 여부 | 이유 |
|---|---|---|
| `INTERNET` | 사용 | 데이터 업데이트, 지도 타일 |
| `ACCESS_COARSE_LOCATION` | 사용 | 가까운 시설 정렬. 대략 위치로 충분하면 이것만 |
| `ACCESS_FINE_LOCATION` | 선택 | 도보 길안내가 필요할 때만. 요청 시 coarse 선택도 허용 |
| `ACCESS_BACKGROUND_LOCATION` | **금지** | 필요 없음. 요청하면 Play 별도 심사 대상 |
| `CALL_PHONE` | **금지** | `ACTION_DIAL` 인텐트로 다이얼러만 연다 (권한 불필요) |
| `POST_NOTIFICATIONS` | 보류 | 알림 기능을 만들 때 상의 |
| 연락처, 카메라, 저장소, 마이크 등 | **금지** | 필요 없음 |

- 권한은 **기능을 처음 쓰는 순간**에 요청하고, 요청 전에 이유를 쉬운 말로 먼저 보여준다(앱 시작 직후 일괄 요청 금지).
- 거부·"다시 묻지 않음" 상태에서도 앱이 정상 동작해야 한다(지역 직접 선택).
- 의존성이 몰래 권한을 추가하지 않는지 병합된 매니페스트(`build/.../merged_manifests`)를 확인한다. 원치 않는 권한은 `tools:node="remove"`로 제거.

## 4. Play Console 제출 항목

- **개인정보처리방침 URL**: 필수. 앱 안(설정/정보 화면)에서도 열 수 있어야 한다. 실제 동작과 일치해야 한다.
- **데이터 보안(Data safety) 양식**: 코드와 SDK가 실제로 하는 일과 정확히 일치해야 한다. 위치를 기기에서만 쓰고 전송하지 않으면 "수집하지 않음"으로 신고할 수 있지만, **지도 SDK가 수집·전송하는 데이터도 포함해야 한다** — SDK 제공사의 데이터 공개 문서를 확인한다.
  - 권한·SDK·통신이 바뀌면 이 양식도 함께 갱신해야 한다. 코드 변경 시 `docs/policy/data-safety-checklist.md`(작성 예정)에 기록.
- **콘텐츠 등급** 설문: 전체이용가 예상.
- **타깃 연령**: 성인 대상(18세 이상)으로 설정. 아동 대상으로 설정하면 가족 정책이 적용된다. 단, 아동 무료급식 정보를 다루게 되면 재검토.
- **광고 포함 여부**: 없음.
- **정부 기관 표방 금지**: 앱 이름·아이콘·설명에서 정부·지자체 공식 앱처럼 보이게 하지 않는다. "공공데이터 기반 민간 앱"이라고 명시한다. 지자체 로고·마크 사용 금지.
- **스토어 등록정보**: 과장 금지("모든 무료급식소", "실시간" 등 사실이 아닌 표현 금지). 스크린샷은 실제 화면.

## 5. 출시 전 체크리스트

- [ ] targetSdk가 현재 Play 요건을 충족
- [ ] 16KB 페이지 크기 호환 확인
- [ ] 병합 매니페스트에 의도하지 않은 권한 없음
- [ ] 위치 권한 거부 상태로 전체 플로우 테스트
- [ ] 비행기 모드(오프라인)로 전체 플로우 테스트
- [ ] 글자 크기 최대 + 저사양 에뮬레이터에서 화면 깨짐 없음
- [ ] 개인정보처리방침이 현재 동작과 일치
- [ ] 데이터 보안 양식이 현재 코드·SDK와 일치
- [ ] 데이터 출처 표기(공공누리 등) 화면 존재
- [ ] 릴리스 빌드에 디버그 로그·테스트 API 키 없음

# 개인정보·위치정보 정책

> 이 앱을 쓴다는 사실 자체가 민감 정보다(노숙, 빈곤, 건강 상태를 드러낼 수 있다). 수집하지 않는 것이 가장 좋은 보호다.

## 원칙: 수집 최소화 → 가능하면 0

| 데이터 | 처리 |
|---|---|
| 현재 위치(좌표) | 기기 메모리에서만 사용. 저장·전송·로그 금지 |
| 검색어, 본 시설, 즐겨찾기 | 기기 로컬에만 저장. 전송 금지 |
| 기기 ID, 광고 ID | 수집 금지 |
| 이름, 전화번호, 계정 | 수집 금지 (로그인 없음) |
| 크래시 정보 | 쓴다면 스택트레이스·기기 모델·OS 버전만. 좌표·검색어 제외. 도입 전 상의 |

## 코드 규칙

- 네트워크 요청 URL·헤더·바디에 사용자 좌표를 넣지 않는다. 데이터 업데이트는 **전체(또는 지역 단위) 파일을 받아서 기기에서 필터링**한다. "내 주변 시설 API"처럼 좌표를 서버로 보내는 구조를 만들지 않는다.
  - 지역 단위로 받을 때도 사용자가 고른 지역(구 단위) 정도만 쓰고, 좌표로 지역을 계산해 보내지 않는다.
- `print`/`Log`에 좌표, 검색어를 남기지 않는다. 릴리스 빌드에서는 로그를 끈다.
- 길찾기는 외부 지도 앱(네이버지도·카카오맵) 딥링크로 넘긴다. 넘길 때 목적지(시설) 좌표만 보내고 출발지는 그 앱이 판단하게 한다.
- **지도 SDK도 데이터를 보낸다.** 지도 타일 요청 자체가 보는 영역을 드러낸다. 사용하는 SDK의 데이터 처리 내용을 확인해 개인정보처리방침과 Play 데이터 보안 양식에 반영한다.
- 새 SDK·새 외부 도메인 통신을 추가하기 전에 반드시 사용자에게 묻는다.

## 한국 법률 (출시 전 전문가 확인 필요)

> 아래는 개발 중 판단을 돕기 위한 메모이지 법률 자문이 아니다.

- **위치정보의 보호 및 이용 등에 관한 법률**: 위치정보를 이용해 서비스를 제공하는 사업자는 **위치기반서비스사업자 신고**(방송통신위원회) 대상일 수 있다. 위치를 기기 안에서만 쓰고 수집·전송하지 않는 구조가 신고 필요성 판단에 어떤 영향을 주는지 출시 전에 확인한다. 이 구조를 유지하는 것 자체가 리스크를 줄인다.
- **개인정보 보호법**: 개인정보를 수집하지 않더라도 개인정보처리방침에 "무엇을 수집하지 않는지, 기기에 무엇을 저장하는지, 어떤 외부 SDK가 무엇을 처리하는지"를 명시한다.
- 위치 이용 약관·동의 화면이 필요한지도 위 확인 결과에 따라 정한다.

## 개인정보처리방침에 들어갈 내용 (초안 골자)

1. 회원가입이 없고 이름·연락처 등 개인정보를 수집하지 않음
2. 위치정보는 가까운 시설을 정렬하는 데 기기 안에서만 쓰고 저장·전송하지 않음
3. 즐겨찾기 등은 기기에만 저장되며 앱 삭제 시 지워짐
4. 지도 SDK(제공사명)가 지도 표시를 위해 처리하는 정보와 해당 제공사 방침 링크
5. 시설 데이터 업데이트를 위해 접속하는 서버와 그 서버가 받는 정보(IP 등 통상 접속 기록)
6. 문의처
